# 数据接入契约 v1

本契约是56号第一轮交付。没有取得真实运营数据；Schema通过不构成法律授权证明，也不代表数据完整、标签成熟或模型可训练。

使用 [bundle.schema.json](bundle.schema.json)；字段字典见 [DATA_DICTIONARY.md](DATA_DICTIONARY.md)。禁止在导出中提供GAID、IDFA、IP、邮箱、手机号、账号ID、设备指纹或可逆身份映射。字段白名单拒绝额外列，但不能检测所有藏在允许字段值中的标识：数据所有者必须在导出前另做隐私检查。

`sample_key`是授权方生成、仅在这一份研究导出内部有效的随机行键；`opportunity_key`与`canonical_economic_key`也是同一导出内的随机关联键。它们仍可能属于受保护的假名数据，不能宣称天然匿名。不得交付原始标识到行键的映射，不能跨导出复用这些键。研究方不建立新身份关联。

跨应用历史应由拥有合法用途授权的运营方在其环境内生成聚合特征，导出只有值、窗口、水位和join contract引用；不导出另一款App的账号或行为明细。运营方需证明：来源控制权、用户同意/其他适用依据、目的兼容性、提供方/接收方、作用域、失效/撤回规则。普通SDK集成或同一发行商关系不构成授权。

## 导出组成

| 表 | 最小内容 | 缺失后不能做什么 |
|---|---|---|
| manifest | 所有者、授权材料引用、目的/应用范围、快照、收入完整水位、延迟宽限、币种和窗口 | 不能开启真实训练；声明必须独立核验 |
| installs | 全体安装者，包括零收入者；安装时刻、国家、平台、版本、广告策略版本 | 不能只交收入用户或广告观看者，否则LTV分母有选择偏差 |
| features | 显式登记的特征值；event/received/source_max_available/computed/available时间及窗口 | 不能把离线回填特征当作当时可用，也不能用未来D0事件预测首次竞价 |
| revenues | 净IAA或已验单净IAP的经济事件；原币金额、精度、阶段、原始/接收/可用时间；跨SDK一致的随机经济键 | 不能混合估算、代理值、metadata价格、paid/fulfilled重复记录 |
| fx_rates | 每币种/收入归属日期唯一汇率；来源、可用时间 | 非USD收入不允许默认为美元，也不接受缺失汇率补1 |
| opportunities（可空） | 实际展示机会、是否展示、安装标签成熟状态、出价时刻、费用、记录策略/选择概率 | 只有安装者时不能评估P(install|impression)；没有未选择机会结果不能作反事实ROAS |

## 收入口径

本契约采用**安装后连续UTC小时、左闭右开**：D0为[0,24h)，D7为[0,168h)，D28为[0,672h)。D1—D28剩余收入为[24h,672h)，不是把“第28自然日”完整包含进来。某些后台以日历D0…D28共29天报告；不得直接拼接，必须换算或保留另一合同版本。本版不兼容自动隐式转换。

IAA收入以同一真实展示的运营方随机经济键去重；MAX→MMP→Firebase多路副本只保留一次。不同事件不可因金额/时间接近而自行合并。精度`exact`只指回调精度声明，不保证最终现金回款；estimated必须单独设定label_precision_scope并报告，不能叫精确结算收入。

IAP必须已验单、明确折扣/税费/商店及支付手续费后的统一净额。paid与fulfilled按同一经济交易去重；差额不能随便择一，而是拒绝等待对账。商品metadata、预测LTV、代理value不进入真实收入标签。税费或退款未知时不得补零再称为净收入。

退款采用**按原购买窗口重述、截至label_as_of快照**：refund金额负数，关联原购买键，recognition_at等于原购买时刻，event_at保留实际退款时刻。汇率采用原购买归属日，以确保同币退款与原收入可对冲。它不是现金流口径。退款/chargeback晚于快照时需生成新标签版本，不声称D28后永远不会退款。

成熟要求：每个安装者+28天+宽限≤label_as_of，且IAA/IAP完整水位均覆盖+28天。宽限不是完整性证明；水位需所有者按网络/地区提供对账依据。没有收入行时，只有完整水位与全安装分母成立才可解释为零，而不是“没有收到所以为零”。

## 时间与预测边界

- `event_at`：源事件发生时刻；`received_at`：定义的采集系统收到时刻；`available_at`：特征/事件可供研究所模拟消费者实际使用的时刻。不是文件修改时间。
- 特征另有`source_max_available_at`和`computed_at`；历史窗口、源可用时间、计算完成和服务可用时间都必须≤预测时刻。仅event_time在竞价前但数据迟到仍属泄漏。
- M0/M1/M2只读opportunity特征，截止严格为bid_at。M3/M4/M5只读安装后24h可用的快照。D0最终收入若+24h尚未可用，只能用当时已知部分，不能事后回填。
- 模型训练与校准还需各自的as-of冻结：训练/校准标签的可用时间和成熟水位须早于随后测试bid时刻。按安装日期排序却使用测试时尚不存在的D28标签，依然泄漏。
- 本轮代码只执行契约、会计、单特征可用性和覆盖检查；没有训练器，不承诺已实现完整的时间外训练或因果评估。

## 接入次序

1. 运营方出具最小范围授权/用途与保留期，独立确认后再决定是否接入。不能只把manifest改成real_authorized。
2. 所有者环境内完成去标识、经济键映射、收入对账和时间水位，导出当前合同允许的列。
3. 先核对聚合安装数/净收入总额、缺失和选择偏差；再在隔离授权位置核验随机行键版，不向生产接口发送任何数据。
4. 契约通过后仍需人工审计授权、成熟、字段血缘、时间外冻结和样本量；通过才开展57—60真实实验。

本轮synthetic runner只接收内置合成fixture。真实训练入口保持关闭；不通过参数或布尔值自动解除。

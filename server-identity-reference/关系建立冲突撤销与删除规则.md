## 状态不是单一合并标签

`PROPOSED → VERIFIED_RELATION / SCORED_CANDIDATE / CONFLICT / ABSTAIN`；只有符合该任务粒度和用途的关系才可物化到membership。VERIFIED_RELATION可指已认证账号控制关系，不能改名为“已证实自然人”。外部服务声明匹配成功也应保留provider_asserted粒度及质量scope；真实准确性须另有合法真值。

`ACTIVE → REVOKED / EXPIRED / SUPERSEDED / DELETION_PENDING`。一个关系可以在历史业务时段有效，但当前用途已撤销；查询不能只看valid_to。权限事件必须覆盖允许读取、允许发送、允许解析、允许特征消费和允许训练等目的，缺失时不默认同意。

## 拆分和冲突

不永久覆盖式union-find。保留relation revisions、不能连接的边、原始证据与membership快照。边撤销后识别影响子图，提升旧membership的invalid_after，阻断相关feature bundle，再以约束重算，发布新版本。新旧簇ID映射仅用于受控迁移与审计，不给消费者提供绕开撤销的历史捷径。

不能把网络/IP、相似设备属性或共同安装App当作自然人认证；本参考架构不采集设备指纹、不训练用于规避隐私选择的真实个人匹配器。研究匹配算法只允许已获相应用途授权的数据或自有测试身份。

## 删除完成标准

1. 授权核对和范围解析：subject/namespace/purpose、有效时点、保留例外与接收方覆盖明确；不把删除请求当新的画像输入。
2. 先发布deny epoch，图谱/特征/consumer均拒旧token；不能等异步后台清理完才阻断读取。
3. 按血缘清原始/派生关系、事件可识别映射、outbox、在线特征、离线快照、缓存、导出，列出partner与备份策略/恢复时重放删除清单。
4. 每个sink确认删除/匿名化/隔离及水位。未确认sink列ACK_PENDING；有法律保留例外则明确目的、期限、访问限制，不能称全量删除。
5. 训练样本移除与已训模型参数处理单列。重训或遗忘是否足够需验证；本设计不承诺能从权重消除所有影响。

PROV-DM的Invalidation是血缘表达（SIR17），不是物理擦除回执；TTL是时间窗口，不是删除/授权证明。不能把Adjust GDPR排队或optout客户端flush视为服务器、partner、训练模型全部删除（AM15–18）。
